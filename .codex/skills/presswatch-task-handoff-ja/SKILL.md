# PressWatch Task Handoff JA

## 目的

PressWatch の一タスクに必要な文脈を保ち、作業開始、完了、次チャットへの引き継ぎで参照先を迷わないようにする。

このスキルは上位の調整役であり、実装、TDD、Git、文書、notesの詳細手順を再定義しない。

## 責務の振り分け

- Phaseブランチ、タスクブランチ、PRのbase: `phase-branch-workflow-ja`
- 製品の振る舞いを追加、変更する実装: `presswatch-tdd-ja`
- `docs/tasks.md` の完了更新: `task-update-ja`
- コミット分割とメッセージ: `commit-message-ja`
- Markdownの書式と検証: `presswatch-markdown-style-ja`
- ユーザーまたは `task.md` が明示した個人メモ: 対応するnotes系スキル

Git操作と秘密情報の承認境界は `AGENTS.md` に従う。

## `task.md` を使う場合

引き継ぎ内容が長い場合、複数案の合意が必要な場合、または作業範囲をチャット間で正確に共有する場合は、プロジェクト直下の `task.md` を一時的な作業仕様として使う。

この方法を使うときは、[`references/task-file-handoff.md`](references/task-file-handoff.md) を全文読み、作成、更新、新しいチャットでの開始、完了後の整理に従う。

`task.md` は一タスク固有の情報を置く場所であり、継続する要件、プロジェクトの進捗、個人の学習記録の正本にしない。

引き継ぎ時点の`task.md`は次タスクの事前設計書にせず、目的、確定済みの範囲、参照する正本、承認境界、完了条件の大筋を共有する。

モデル配置、制約名、テストケース、実行コマンドなど、次タスクで既存実装を確認して決められる詳細は、ユーザーがすでに確定した事項または安全上欠かせない条件を除き、次タスクの調査と必要に応じたPlanへ委ねる。

## 作業開始時

1. `AGENTS.md` と、存在する場合は `task.md` を読む。
2. `git status --short --branch` で、現在ブランチと未コミット差分を確認する。
3. 指定されたPhaseブランチ、直前のPR、ローカル参照が、現在のGit状態と一致するか確認する。
4. ブランチ操作が必要な場合は、`phase-branch-workflow-ja` に従って提案し、了承を待つ。
5. 未確定の設計判断や複数案の比較が必要なら、編集前にPlanモードを提案する。
6. タスクに必要なコード、テスト、docs、スキルだけを確認する。

古い引き継ぎ情報を現在の状態として扱わず、確認した事実と未確認事項を分けて報告する。

## 作業中

- `task.md` に確定事項を反映する場合は、ユーザーが合意した範囲だけを更新する。
- 詳細手順は、作業内容に対応する下位スキルへ委譲する。
- notesは、ユーザーの依頼または `task.md` の明示がある場合だけ作成、更新する。
  `references/task-file-handoff.md` にあるタスク完了時のnotesへの移動も、この条件を満たす場合に限る。
- 継続して共有すべき要件や手順が確定した場合は、保存先と理由を提案してから適切なdocsへ移す。

## 完了と引き継ぎ

- タスク固有の検証、差分レビュー、Git状態の確認は、`task.md` と選択した下位スキルに従う。
- 次のチャットへ進む場合は、詳細な作業仕様をプロンプトへ重複させず、`AGENTS.md` と `task.md` の絶対パスを示す。
- `task.md` の整理、置き換え、削除は `references/task-file-handoff.md` に従う。
- commit、push、PR作成などの操作は自動実行せず、`AGENTS.md` の承認境界に従う。
