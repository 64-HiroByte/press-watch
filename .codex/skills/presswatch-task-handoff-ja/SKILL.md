# PressWatch Task Handoff JA

一タスクの目的、確定事項、未確定事項、承認条件を次の作業へ引き継ぐ。
Git操作と秘密情報は`AGENTS.md`、文書の正本は同ファイルの「情報の正本」に従う。

## 開始時

- `AGENTS.md`と存在する場合は`task.md`を読み、`git status --short --branch`で現在の状態を確認する。
- 関係するPhase・直前のPR・ローカル参照を照合し、過去の記録と現在の事実、未確認事項を分ける。
- ブランチを扱う場合は`phase-branch-workflow-ja`を使う。
- 未確定の設計、影響範囲の広い判断、複数案の比較が必要なら、編集前にPlanモードを提案する。

## `task.md`の操作

長い引き継ぎや作業範囲の共有には、プロジェクト直下の`task.md`を使う。
短く明確で既存文書だけで開始できる場合は、短い依頼プロンプトでよい。

[引き継ぎ手順](references/task-file-handoff.md)から、該当する節だけを読む。

- 作成・置き換え: 「作成前の確認」「記述する粒度」「`task.md` に含める内容」
- 開始プロンプト: 「新しいチャットの開始プロンプト」
- 作業中の更新: 「作業中の更新」
- 完了後の整理: 「タスク完了時」

引き継ぎプロンプトには`AGENTS.md`と`task.md`の絶対パスを示し、詳細仕様は重複させない。
実装・文書更新は、その作業に対応するスキルへ委ねる。
