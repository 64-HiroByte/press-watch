# Commit Message JA

## 分割

`git add`の前に、目的と責務ごとの分割案とメッセージ案を示す。
Git操作の承認は`AGENTS.md`に従う。

- 一つのコミットを、単独で説明・レビュー・取り消しできる責務にまとめる。
- 同じ振る舞いの実装と、それを直接保証するテストは同じコミットにする。
- 独立した責務は、同じ機能やtypeでも分ける。
- 継続文書は、実装と独立して確認できる変更目的がある場合に`docs`コミットへ分ける。
- 分割するとテストが失敗する、または変更の意味が成立しなくなる場合は、まとめる理由をステージ前に説明する。

各コミットに必要な検証が成功する状態を候補とする。
提案は候補差分に、実行するコミットのメッセージはステージ済み差分に合わせる。

## メッセージ

```text
<type>(<scope>): <日本語の要約>
```

- 原則1行とし、背景・制約・判断理由が伝わらない場合だけ本文を加える。
- scopeは明確な場合だけ付ける。
- 要約は自然な日本語とし、命令形を強制せず、末尾に句点を付けない。

| type | 用途 |
| --- | --- |
| `feat` | 利用側から見える機能追加 |
| `fix` | バグ修正と、それを保証するテスト |
| `docs` | 文書や作法の追加・修正 |
| `test` | テストコード・説明だけの追加・修正 |
| `refactor` | 振る舞いを変えない整理 |
| `chore` | 開発補助、設定、メタデータ |

例: `feat(scraper): 環境省の報道発表取得を追加`
