# PressWatch - Tasks

## 方針

- 1タスク = 1責務 を意識する
- 各タスクはレビューしやすい粒度に分ける
- まずはMVP完成を優先する
- いきなり全部作らず、土台 → データ取得 → 保存 → API → 画面 の順で進める
- Codex には小さな単位で依頼し、差分ベースでレビューする

## Phase 5: API実装

Phase 5 では、保存済みの報道発表をフロントエンドから利用するための API を実装する。
開始準備として、管理 PostgreSQL に Supabase を採用し、ローカル環境を PostgreSQL 17 へ変更してから API 実装へ進む。
最初の API 実装範囲は、ヘルスチェック、一覧取得、新着順、ページネーション、タイトル検索までとする。
独自カテゴリは、旧 Topics Checker のCSVから正規化し、水関連分野を見直した初期データを使う共有の固定カテゴリとして扱う。
ブックマーク、ユーザー登録、ユーザー定義カテゴリはMVP後に扱う。

- 差分ベースでレビューする

- main ブランチとの差分で確認しやすい単位を保つ
