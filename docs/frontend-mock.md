# 一覧Mockの画面構成と確認方法

## 目的と現在の位置づけ

Phase 6-3では、固定データによるMockをPCで確認し、一覧の配置・情報量・文字サイズ・カテゴリ表示・操作部品の配置について合意する。
画面の内容は架空のサンプルであり、API・DBや環境省サイトから取得しない。
初版の3案に2カラムのD・サイドバー案を追加し、4案を比較した。
2026年10月6日、ユーザーとの比較によりD案を採用した。
同日、ユーザーの方針によりMockをD案へ固定し、デザイン・カテゴリ欄の比較操作を外した。
各表示状態を含む最終確認とPhase 6-3の完了判断は別途行う。

グラデーションや装飾的な背景を使わず、ライトは温かみのあるグレー・チャコール、ダークは既存Neutralテーマを基調とする。
細い罫線、控えめな角丸、余白と整列によって情報を整理し、ライト・ダークとも文字とフォーカスの読みやすさを優先する。
新しい依存、外部フォント、画像、装飾的なアニメーションは追加しない。
テーマ切り替えの選択背景にだけ、ユーザーが希望したスライドアニメーションを使う。

### ライトモードの配色

純白のまぶしさを抑えるため、Mockのライトモードだけに次の配色を適用する。
背景は画面の高さまで塗り、データなし等の短い表示でも下側に白い余白を残さない。
ダークモード、共有テーマ変数、案内画面と基本部品確認ページは変更しない。

| 用途 | 色 |
| --- | --- |
| 画面背景 | `#e4e3dc` |
| 主要な文字 | `#303630` |
| 確認欄・ホバー背景 | `#d8d7ce` |
| 日付・補助文 | `#585e56` |
| 検索ボタン | `#3b443b` |
| 区切り線 | `#c3c1b6` |
| 入力欄の枠線 | `#797f73` |
| フォーカス表示 | `#687660` |

主要文字・補助文・ボタンの文字は、[W3Cの文字コントラスト基準](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)の4.5:1以上を目安に配色値を確認する。
まぶしさの感じ方はユーザーのブラウザで確認し、見た目の合意は別途行う。
2026年10月6日、ユーザーが`#e4e3dc`の背景を確認し、ライトモードの配色に合意した。

### ピル外枠と表示用バッジ

背景は既存の`oklch(0.145 0 0)`を使い、純黒ではなく約`#0a0a0a`のグレーとする。
カテゴリ選択・テーマ切り替えのピル外枠に`#6f736b`を使い、通常の区切り線より見分けやすくする。
カテゴリの選択時は従来どおり明暗を反転し、外枠も文字と同じ色にする。
ライトモードのピル外枠には、この上書きを適用しない。
報道発表・適用中カテゴリ・長いカテゴリ名の見本の表示用バッジは、ライトでは`#c5c6bb`、ダークでは既存の`--muted`の背景で塗りつぶし、文字に`--foreground`を使う。
枠線は透明にし、選択中のピルの明暗反転と区別できる控えめな塗りつぶしにする。
表示用バッジは角丸3pxの形状を維持し、クリックや選択操作は追加しない。

## 採用した構成と比較理由

D・サイドバー案を採用し、検索欄とカテゴリ選択を左、報道発表一覧を右に配置する。
カテゴリ選択は合意済みのピル型ボタンを使い、適用中カテゴリを右側ヘッダーに表示する。
発表ごとの所属カテゴリはタイトルの近くに置く。

B・余白案は余白の多い構成を採用しないというユーザーの判断により選ばない。
C・コンパクト案はカテゴリを右端に寄せると視線が届きにくいため選ばない。
A・標準案とD案はタイトルの近くにカテゴリを置く点を共通とし、検索条件をサイドバーに配置できるD案を選ぶ。
A・B・Cは文書とGit履歴に比較の記録を残し、以後の画面表示と見た目の調整はD案を基準にする。
画面構成の合意は検索・絞り込み機能の実装完了を意味しない。
検索条件の適用タイミングは以下の追加方針に記録し、未確定事項と区別する。

## 4案の比較履歴

いずれも横区切りの一覧形式とし、同じ固定データと表示状態で比較する。
操作部品は既存部品を使い、D案では検索・カテゴリ欄の配置とヘッダーへのカテゴリ表示を比較する。

| 案 | 配置と表現 | 比較する観点 |
| --- | --- | --- |
| A・標準 | 最大幅1,120px、日付を左、タイトルとカテゴリを右へ配置する | 一覧性と読みやすさのバランス |
| B・余白 | 最大幅960px、見出しを明朝系、日付・タイトル・カテゴリを縦に配置する | 長いタイトルの読みやすさ、余白の量 |
| C・コンパクト | 最大幅1,120px、日付・タイトル・カテゴリを横に配置する | 一画面の情報量、カテゴリ欄とタイトル幅のバランス |
| D・サイドバー | 最大幅1,280px、左248pxに検索条件、間隔32pxで右に一覧を配置する | 条件と一覧の見分けやすさ、選択カテゴリの確認、一覧の幅 |

タイトルは全案16px・行間1.7とし、全文を表示する。
カテゴリは色に依存しないBadgeで表示し、複数のBadgeと長い名前を折り返す。
所属カテゴリがない場合は「カテゴリなし」と表示し、「その他」へ置き換えない。
画面の表示・選択にはPressWatchの10固定カテゴリを定義順で使い、`source_categories`は表示しない。

A・B・Cのカテゴリ欄はピル形状のトグルボタン案とNative Select案を切り替えて比較した。
現在のD案は採用済みのピル形状に固定し、比較用の「カテゴリ欄」は表示しない。
トグルボタンは未選択時に背景なしの枠線、選択時に明暗を反転した背景と文字で区別する。
チェック印は表示せず、両端を丸くした28px高のピル形状とする。
文字は13px・行間18px、左右余白14px、ボタン間隔6pxとし、検索欄・カテゴリ欄の上下余白も抑える。
オン・オフで文字・余白・太さを変えず、ボタンの幅を維持する。
Mock内では複数ボタンを独立してオン・オフでき、初期状態はすべて未選択とする。
既存Buttonを使い、`aria-pressed`で選択状態を伝え、Space・Enterで操作できる。
2026年10月6日、カテゴリ選択の見た目は現在のピル型ボタンを採用することでユーザーと合意した。
製品の単一／複数選択仕様の確定を意味しない。
入力・選択値は表示見本の比較中だけ扱い、一覧を変更しない。

## D・サイドバー案

表示はD案に固定する。
左にはPressWatchの名称、キーワード入力、公開日の開始日・終了日、入力欄と同じ幅の検索ボタン、10固定カテゴリのピルを順に置く。
検索欄のplaceholderは、サイドバー内で全文が読める「タイトル内のキーワード」とする。
右との境界は細い縦罫線とし、サイドバーはページ全体と一緒にスクロールする。
独立したスクロールや固定追従は追加しない。
幅768px未満では検索条件を左から開くドロワーへ収め、一覧を1カラムで表示する。

テーマ切り替えはメインコンテンツのヘッダー右上に、「報道発表一覧」の見出しと同じ行で配置する。
画面上の「テーマ」の文字は表示せず、グループの読み上げ名を「表示テーマ」とする。
テーマは太陽・月の2つのアイコンをピル型のグループ内に置き、ライト・ダークを直接選ぶ。
選択中のアイコンの背面をピル形状にし、切り替え時は180msで左右にスライドさせる。
システム設定の選択肢は表示せず、保存済みの設定がシステムの場合は現在の明るさを選択表示に使い、クリック後はライト・ダークを保存する。
初期表示ではスライドさせず、動きを減らす設定ではアニメーションを省く。
選択中は背景と文字の明暗を反転し、`aria-pressed`、読み上げ用の名前と`title`で状態・用途を伝える。
操作領域は44pxとし、Tab・Space・Enterで操作できる。
既存のThemeProviderとnext-themesの保存処理を使い、共有のThemeSelectorと基本部品確認ページは変更しない。
スマホ幅でもドロワーの外にある一覧ヘッダーから切り替えられる。
幅が足りない場合はヘッダー内で折り返して右寄せにし、適用中カテゴリはその下に表示する。

右のヘッダーには「報道発表一覧」と「適用中カテゴリ」を表示する。
初期状態は未選択で「すべてのカテゴリ」と表示し、左のピル選択に連動して定義順のカテゴリ名へ置き換える。
カテゴリ名は表示用Badgeとして折り返しを許可し、解除ボタンは付けない。
その下に既存の件数・並び順、公開日を左に置くA案と同じ一覧、ページ送りを表示する。
長いカテゴリ名の確認欄も右側の一覧と同じ幅を使う。

適用中カテゴリは選択に連動する表示見本であり、実際に一覧へ適用した検索条件を表すものではない。
確認画面の説明にも、一覧・件数・ページ位置が固定であることを明記する。
カテゴリの選択状態は表示状態を切り替えても保持する。
カテゴリの単一／複数選択など、残る製品の操作仕様はPhase 6-4で別途決める。

### 狭い画面の検索条件ドロワー

2026年10月6日、狭い画面でサイドバーをハンバーガーメニューへ切り替える案をMockで試すことになった。
幅768px未満では、一覧上部にPressWatchの名称と「検索条件」の文字を添えたメニューボタンを置く。
ドロワーは初期状態で閉じ、開いた間は背景の一覧・比較欄の操作とページスクロールを抑止する。
幅768px以上では現在の2カラム表示を使う。
2026年10月6日、狭いPCウィンドウでもサイドバーを使えるよう、ユーザーの方針によりスマホ幅での切替へ変更した。
導入済みの[Tailwind CSSの既定の`md`](https://tailwindcss.com/docs/responsive-design)を基準とし、端末の種類ではなく画面幅で判定する。

ドロワーは左端に置き、幅は最大320px、画面右側には最低32pxを残す。
高さは画面いっぱい、内側の余白は24pxとし、内容が収まらない場合はパネル内をスクロールする。
上部に検索条件の見出しと閉じるボタンを置き、検索条件・カテゴリの順序、ピルと仕切り線の余白を維持する。
背景は黒の45%透明度の単色とし、グラデーションや開閉アニメーションは追加しない。
開閉ボタンの操作領域は最低44pxとする。

検索ボタンのクリックで閉じるが、カテゴリ選択では開いたままとする。
閉じるボタン、背景でのクリック、Escapeでも閉じられる。
閉じたり画面幅を変えたりしても、キーワード・公開日・カテゴリ選択を保持する。
開閉前後で一覧のスクロール位置を維持する。
検索結果・件数・ページ位置・URLは固定のままであり、ドロワーの開閉を製品の検索処理と区別する。

開いたときはパネル見出しへフォーカスを移し、Tab・Shift+Tabを内部で循環させる。
通常の閉操作ではメニューボタンへ戻し、閉じた検索欄にはTabで移動できないようにする。
幅768px以上へ戻すとモーダルを解除し、再び狭くすると閉じた状態に戻す。
幅変更でフォーカス対象が隠れる場合は、狭い画面ではメニューボタン、広い画面ではキーワード欄へ移す。

Mock専用の`MockSidebarFilters`が標準の`dialog`で開閉を管理し、狭い画面では`showModal()`を使う。
広い画面では同じ入力部品を通常フローの非モーダル表示として使い、開閉や幅変更で入力部品を複製・再マウントしない。
広い画面の表示はCSSで保証し、`dialog`の開状態だけに依存させない。
画面のリサイズでも開状態を同期し、狭い画面内でのリサイズでは開いたドロワーを維持する。
新しい依存は追加せず、検索欄・一覧・表示状態のServer Componentを再利用する。

## 公開日入力の追加方針と検索条件の適用

2026年10月6日、ユーザーから公開日でも検索できるようにする方針が示された。
サイドバーは、キーワード、公開日、検索ボタン、カテゴリの順に配置する。
公開日は開始日・終了日の期間入力とする。
検索ボタンとカテゴリの間に余白と細い仕切り線を置き、適用タイミングの異なる操作を分ける。
MockにはD案だけに既存Inputの`type="date"`を追加し、検索ボタンの上に開始日・終了日を縦に配置する。
カテゴリ上の仕切り線は1pxとし、線の上下にそれぞれ32pxの余白を置く。

キーワードと公開日は入力しただけでは一覧へ適用せず、検索ボタンのクリックで適用する。
カテゴリは選択時に一覧へ即時反映し、検索ボタンのクリックを待たない。
これらは製品の操作方針であり、現在のMockでは一覧・件数・ページ位置を変えない。
現行の一覧APIに公開日条件はないため、機能化には一覧APIの拡張が必要である。
キーワード・公開日は入力中と適用済みの条件を区別し、カテゴリ変更は最後に検索したキーワード・期間に対して適用する。
カテゴリ変更によって、未検索の入力値を適用しない。
検索ボタンを押したときは選択中のカテゴリを維持し、新しいキーワード・公開日を適用する。
一覧ヘッダーには、適用済みのキーワード・期間・カテゴリを表示する方針とする。
現在のMockでヘッダーへ連動するのはカテゴリだけであり、キーワード・公開日は入力欄の表示見本とする。
日付の範囲や未指定時の扱いはPhase 6-4で確定する。

## 表示状態

比較欄の「表示状態」で次の見本を切り替える。
各見本は通信や入力内容と連動しない。

| 状態 | 一覧領域 | 件数・ページ送り |
| --- | --- | --- |
| 通常一覧 | 8件のサンプル、長いタイトル・複数カテゴリ・カテゴリなしを含む | 128件中1–8件、1／16ページの固定見本 |
| ローディング | 読み込み中の文言と静止したスケルトン | 表示しない |
| 取得失敗 | 取得できなかった旨と案内文 | 表示しない。0件として扱わない |
| データなし | 報道発表がまだない旨 | 0件、ページ送りなし |
| 検索結果なし | 条件に一致する報道発表がない旨 | 0件、ページ送りなし |

件数とページ数はMock用の数値であり、製品のページサイズを確定しない。
検索ボタンは送信しない通常ボタンとし、検索欄はフォームに入れない。
詳細リンクとページ送りはフォーカス可能とし、MockのClient側の枠内でクリック・補助クリックによる遷移を抑止する。
キーワード入力中のEnterや選択操作を含め、一覧・件数・現在ページ・URLは変更しない。

現行固定カテゴリの名前は短いため、「長いカテゴリ名のレイアウト確認」を開いて専用見本を確認する。
検証専用カテゴリは通常の選択肢へ追加せず、実カテゴリの定義を変更しない。
この見本にも通常一覧と同じ幅・表示部品・デザインを適用する。

## 構成と既存画面への影響

- `/mock`はdevelopment限定とし、Serverページの先頭でproduction等を404にする。
  既存案内画面と`/ui-foundation`は維持する。
- 再利用する表示部品は`apps/web/components/press-releases/`、固定データは`apps/web/mock/`へ分ける。
  表示部品の型は表示用の内部型であり、公開APIのDTOを定めない。
- ページはServer Componentとし、検索欄と5表示状態の内容をServerで組み立ててReactNodeとして確認枠へ渡す。
  表示状態の切替、トグルボタンの表示用選択状態、リンク遷移の抑止、テーマ・入力部品など必要な部分だけClient側で動く。
  ピルの描画部分は制御可能なMock専用部品として共用する。
  D案の選択状態は確認枠のClient Componentで管理し、一覧へ渡さない。
  カテゴリの表示情報だけをServerページから確認枠へ渡し、選択に連動するヘッダーをClient側で描画する。
  ドロワーの開閉と検索ボタンクリックによる終了もMock専用のClient部品で扱う。
- CSSはMockルートに置き、Mockのクラス配下へ限定する。
  選定したデザインを本実装へ引き継ぐ際は、表示部品と対応するスタイルを合わせて移す。
  共有Badgeの既定スタイルは変更せず、Mock側の指定で長い名前の高さ・折り返しを調整する。
  ドロワーをモーダルで開いている間だけ、Mockのパネルを条件とした`html:has(...)`でページスクロールを抑止する。

採用部品とテーマは[UI基盤](frontend-ui.md)を参照する。

## 起動と確認

[Web単体の起動・型チェック・ビルド](local-development.md#フロントエンドを単体で起動する)の既存手順を使う。
検証時は必要なWebソース・設定・lockfileだけを一時環境へコピーし、秘密ファイル・既存依存・生成物は含めない。
一時環境で次を実行する。

```bash
pnpm install --frozen-lockfile
pnpm --filter @press-watch/web exec next typegen
pnpm typecheck:web
pnpm build:web
pnpm dev:web --hostname 127.0.0.1 --port 3103
```

閲覧先は`http://127.0.0.1:3103/mock`とする。
ポート使用中は空いている別ポートを指定し、実際の確認URLをユーザーへ提示する。

- 1280×720・1440×900を目安に、サイドバーとピル型ボタンを使うD案で5表示状態を確認する。
  ライト・ダーク、日本語の文字サイズ、余白、長いタイトル、カテゴリの有無を確認する。
- 未選択・一部選択・全10カテゴリ選択・全解除を試し、ヘッダーとピルの一致、定義順、表示状態切替後の選択保持を確認する。
  幅768px未満のドロワーと768px以上のサイドバーも確認する。
- 狭い画面では、開閉・検索で閉じる・カテゴリでは閉じない・背景クリック・Escape・Tab循環を確認する。
  入力値・選択と一覧のスクロール位置の保持、幅変更後のフォーカスと背景操作の復帰も確認する。

塗りつぶしの実画面での目視確認はブラウザ操作制限により未実施である。

## Phase 6-4へ残す事項

キーワード・公開日は検索ボタンで適用し、カテゴリは選択時に即時反映する方針は合意済みである。
カテゴリは最後に検索したキーワード・期間に対して適用し、新しい検索では選択中のカテゴリを維持する方針も合意済みである。
公開日の範囲・未指定時の扱い、カテゴリの単一／複数選択、条件変更時のページ位置、ページサイズ、URL状態、戻る操作、API接続・キャッシュ方針は未確定とする。
